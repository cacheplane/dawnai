# v0.8.22 Duplicate Draft Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Safely quarantine the two duplicate v0.8.22 escrow drafts, resume the canonical exact-tag release, publish the README-bearing v0.8.23 fixed group, and remove the one-time recovery surface.

**Architecture:** Build a temporary candidate-pinned operator command with a pure evidence/state core, a bounded read-only production adapter, and a narrow recovery-only writer. The command captures short-lived canonical evidence, resumes four exact duplicate states idempotently, archives each original body before removing its live marker, and leaves normal controller duplicate detection unchanged. After production convergence, the existing `release.yml` owns npm publication and the temporary command is removed.

**Tech Stack:** Node.js 24 ESM, `node:test`, existing Dawn release readers and controller primitives, GitHub REST API, npm registry metadata, canonical JSON/SHA-256 receipts, pnpm 10.33.0.
